How UnixDatagramIPCTransport tells other processes a transaction committed

Every process that opens an OrbitIPCDatabase joins a shared coordination directory, binds one Unix datagram socket, and advertises the regions it cares about in marker files. A commit is sent only to the peers whose advertised region it concerns, and a send never waits: a peer with no room is owed the commit's region instead. One event-loop thread per transport receives datagrams and sends full peers what they are owed, with no broker and no Dispatch.

02

Discovery through the coordination directory

Processes find each other through the filesystem: sockets in v1/s/, and one marker per endpoint per database in v1/d/<coordinationKey>/. Markers are replaced whole with a rename. Each sender's registry keeps the peer regions it read until a directory watch reports a change. The next scene goes through each file.

06

Owed regions for full peers

What happens when a peer's receive queue is full. A send never waits for it. The peer is owed the commit's region instead, merged with anything else it is owed for that database, and the endpoint's thread sends it what it is owed once it has room. Pick a scenario to see each way an owed region ends: it is delivered, the peer stops advertising the database, or the peer turns out to be dead. None of them has a deadline.

07

The event loop: Darwin and Linux/Android

One “Orbit IPC” DetachedThread per transport blocks in UnixEventQueue.wait(until:). The two platforms differ in one important way: Linux can report when a full peer has room, and Darwin can't, so Darwin retries on a timer that backs off to once a second.

08

Region widening for value observations

An observation whose fetch reads more than it had advertised must not miss a commit to the new part. It widens its advertisement first, and updateRegion(_:) returns only after the new marker is on disk. Then it reads again. Compare the real order with the order that would lose a commit.

How UnixDatagramIPCTransport tells other processes a transaction committed

Every process that opens an OrbitIPCDatabase joins a shared coordination directory, binds one Unix datagram socket, and advertises the regions it cares about in marker files. A commit is sent only to the peers whose advertised region it concerns. One event-loop thread per transport moves the datagrams, with no broker and no Dispatch.

Architecture map

The components of one process's transport and how they connect. Tap or hover a component to see what it does and where it lives; the steps trace one commit from a write to the peers and back into an observation.

02

Discovery through the coordination directory

Processes find each other through the filesystem: sockets in v1/s/, and one marker per endpoint per database in v1/d/<coordinationKey>/. Markers are replaced whole with a rename. Each sender's registry keeps the peer regions it read until a directory watch reports a change.

03

Commit fan-out with sender-side filtering

A commit goes only to peers whose advertised region it concerns, so a process that doesn't care is never woken. Pick a commit to see which peers it reaches.

04

Wire format byte inspector

The bytes below are computed in the page by a port of UnixDatagramWireBatch.encoded() and UnixDatagramWireProtocol.encodeMarker(_:). Hover or tap a byte, or a row in the field list, to see which field it belongs to, its offset and its decoded value. Toggle commits to watch the shared string table change.

05

Batching under backpressure

What happens when a peer's receive queue is full. With .suspend(upTo:), messages wait in order in one FIFO per peer and go out together once the peer has room, each sender waiting on its own continuation. With .fail, nothing waits.

06

The event loop: Darwin and Linux/Android

One “Orbit IPC” DetachedThread per transport blocks in UnixEventQueue.wait(until:). The two platforms differ in one important way: Linux can report when a full peer has room, and Darwin can't, so Darwin retries on a timer that backs off.

07

Region widening for value observations

An observation whose fetch reads more than it had advertised must not miss a commit to the new part. It widens its advertisement first, and updateRegion(_:) returns only after the new marker is on disk. Then it reads again. Compare the real order with the order that would lose a commit.

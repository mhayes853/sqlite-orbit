03 / Beyond ordinary test runs

Where coverage stops being a percentage.

These are limits on what the current evidence establishes, not confirmed defects. Tests can reproduce selected conditions; they cannot exhaust every schedule, device, storage stack or length of operation.

Two different kinds of unknown: an unexecuted API path can usually be covered with a conventional test. The boundaries below remain relevant even when every source line executes and the platform matrix is green. The file measurements and matrix show the first kind; these cards describe the second.
Scheduling

Rare concurrency interleavings

Existing evidence
Queue and pool stress tests, controlled observation races, cancellation probes, worker lifecycle checks and subprocess contention exercise selected schedules.
What remains uncertain
Different core counts, scheduler decisions, cancellation timing and long chains of overlapping reads, writes and subscriptions can produce orders absent from a finite run.
Limit of the evidence
A passing stress run demonstrates those observed executions; it does not establish that every possible interleaving is safe.
Storage & recovery

Machine failure during persistence

Existing evidence
Rollback, commit-failure handling, WAL checkpoints, reopening database files and killed-process tests cover application-level recovery scenarios.
What remains uncertain
Power loss, kernel failure, filesystem behavior and device write caching can affect which database and coordination-file changes actually reach persistent storage.
Limit of the evidence
Killing a process is not equivalent to losing power. Injecting a SQLite error also does not reproduce the full storage stack.
Operating-system lifecycle

Real app, widget and notification behavior

Existing evidence
The repository includes SwiftUI rendering and binding tests, Reminders widget queries, notification-center fakes and Unix process suspension tests. Apple tests were not run in this Linux measurement.
What remains uncertain
Device background limits, app and widget suspension, OS termination, permission changes and actual notification delivery involve services outside the database library.
Limit of the evidence
A successful fake notification request or simulated view update does not establish when the operating system will display it or resume an application.
Time & load

Sustained operation at production scale

Existing evidence
Finite contention and cancellation workloads check progress; targeted counters check resource cleanup. An opt-in scan benchmark compares pool and queue execution.
What remains uncertain
Long-lived subscriptions, large databases, skewed queries, receiver backlogs and repeated failures may expose memory growth, latency tails or starvation over hours or days.
Limit of the evidence
Short correctness runs and one scan workload cannot characterize all workload shapes or establish a stable long-term resource profile.
Deployment environment

Engine, kernel and filesystem combinations

Existing evidence
CI defines system SQLite, SQLCipher, selected Turso and Apple test jobs, plus Android and WASI builds. Path, symlink and IPC tests exercise the environment in which they run.
What remains uncertain
SQLite builds and versions, OS revisions, directory permissions, filesystem semantics and deployment configuration create combinations beyond a practical CI matrix.
Limit of the evidence
A build proves compilation for that target. A test run establishes behavior only for its exercised configuration; neither transfers automatically to every deployment.
Application integration

Caller-defined queries and extension behavior

Existing evidence
Typed and raw SQL, region tracking, migrations, registered functions and collations, and the Reminders application cover representative uses of the public API.
What remains uncertain
Applications can introduce new schemas, triggers, migration histories, callbacks and query shapes whose interactions are not represented by those fixtures.
Limit of the evidence
Passing the package suite establishes the tested contracts for its inputs, not correctness of arbitrary application logic built on top.
